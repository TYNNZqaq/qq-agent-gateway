# 项目专责 Agent 团队

QQ Agent Gateway 的维护由主负责 Agent 统一统筹，功能、发布和文档 Agent 分工协作。这描述的是项目开发方式；用户安装程序后，不会因此额外启动一组后台开发 Agent。

| 角色 | 负责内容 | 交付给负责人的结果 |
| --- | --- | --- |
| 主负责 Agent | 任务拆分、文件归属、接口协调、整合、验收、发布和用户汇报 | 可使用的功能、可核对的证据、发布链接及剩余事项 |
| 功能 Agent | 登录接入、自动初始化、本人配对后的配置、业务与管理界面 | 最小可回退修改、相关测试和状态说明 |
| 发布 Agent | 白名单导出、依赖与许可核对、隐私扫描、清单和 ZIP | 干净源码包、Windows 程序包、SHA256SUMS 和审计结果 |
| 文档 Agent | README、用户指南、团队规则和第三方声明 | 与代码一致且不含本机信息的公开文档 |

各专责 Agent 可独立完成被分配的工作面，主负责 Agent 对最终整合质量和对用户的说明负责。需要多个工作面时并行推进；共享目录中一个文件只由一个 Agent 修改，交叉接口先同步。

## 协作流程

1. 负责人明确目标、范围、当前授权和实际环境，分配专责 Agent 与文件边界。
2. 专责 Agent 阅读现有实现，先同步接口方案，在独立候选树内实现；真实实例的操作交由负责人统一安排。
3. 以具体行为和测试结果交接，说明已验证、待验证及不确定状态；文档根据最终实现调整。
4. 负责人整合代码，运行所需回归、边界检查及发布审计，确认原资料与服务保留，再构建产物。
5. 负责人执行用户已授权的发布并报告可用入口。用户需要介入时，说明具体阻碍、来源和已经完成的准备。

## 共同约束

保留配对、账号隔离、项目授权、执行证明和本机授权边界；不为测试强停其他应用、不复制对方凭据或私有运行库。可复用代码使用动态路径。源码和程序包只包含公开白名单，不带使用者实例、会话、备份或凭据。

离线测试证明的是实现行为；真实通信、原生写入、模型执行、冷启动及新机安装需各自取得证据。发布说明应明确实际范围，避免把“已实现”“已配置”和“已实测”写成同一件事。

详细的执行规则见根 [AGENTS.md](../AGENTS.md)。
