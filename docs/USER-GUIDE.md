# 用户指南

QQ Agent Gateway 把本机 Codex 与你自己的 QQ 机器人连接起来。本指南面向全新下载和已有实例升级；程序包不预装任何人的账号、机器人或业务记录。

## 准备环境

- Windows，以及可从 `PATH` 找到的独立 Node.js 24 或更新版本。
- 兼容的官方 Codex CLI。网关使用自己的账号目录登录，不共用桌面应用的登录库或私有运行时。
- 使用桌面通知、原生 Q 和已有会话控制时，需要同一 Windows 用户的 Codex 桌面及已初始化的本机会话目录。
- 自己在 QQ 开放平台创建并可使用的机器人，以及 AppID/AppSecret。
- 非系统盘上的独立程序目录和数据目录。不要选择盘符根、用户目录根、桌面根或其他应用的安装目录作为共享项目/数据根。

在 PowerShell 中执行 `node --version`、`codex --version` 可核对是否能找到公共程序。Node.js 可以正常安装在系统盘；这里限制的是本项目业务数据的存储位置。

## 安装

Windows 程序 ZIP 已包含本项目锁定的 npm 运行依赖，解压后双击 **安装.cmd**。如果使用源码 ZIP 或 Git 克隆，先在源码目录运行 `npm ci`，再双击 **安装.cmd**。不要同时启动同一机器人的多个解压副本。

安装会打开本机管理台，并为当前 Windows 用户注册 Codex 启动连接监听器。它使用当前用户的 Startup 已知文件夹，不安装系统级常驻服务，也不修改其他应用的启动项。仅打开管理台不会替你登录、提供 QQ 凭据或进行本人配对。

默认地址为 `http://127.0.0.1:17391`；端口占用时会另选端口。再次双击 **打开管理界面.cmd** 会核对并复用已运行的管理台。

如果需要自选数据目录，在程序目录运行以下命令，并把占位内容换为实际的非系统盘独立目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1 -RuntimeDirectory "<独立数据目录>" -OpenBrowser
```

命令中的执行策略仅用于这次脚本进程，不需要更改机器的全局执行策略或目录权限。

## 首次登录与自动配置

1. 在「QQ 机器人」登记自己的机器人，在「Agent 实例」登记 Codex，建立机器人与实例的绑定。
2. 在「接入 → Codex」通过官方页面完成本人登录，刷新状态并选择模型；填写自己的 QQ AppID/AppSecret，核对平台连接状态。网关账号与 Codex 桌面账号各自保存。
3. 阅读管理台列出的处理范围并明确同意。可先使用桌面原生连接，不要求先授予独立工作目录权限。原生会话观察范围与工作模型项目授权分开：允许接收本机原生会话通知，不会授予网关模型任意目录读写权限；原会话控制仍核对来源、所属项目、本人绑定和原回合。
4. 条件齐备后，向导自动准备本实例业务数据、发起本人 QQ 配对。配对码只在当前管理窗口展示；本人须在有效期内把它发送到自己的机器人私聊。
5. 配对成功后，自动配置通知、原生 Q 和原会话控制，并启动原生连接服务。此模式不在后台发起独立模型自检；如果桌面尚未初始化或协议不可用，管理台会显示待就绪原因。
6. 如需 QQ 独立聊天或发起新任务，先在本机正常「停止机器人服务」，授权具体工作项目及其读写、命令权限，再主动运行「Codex 实际自检」。通过并取得有效证明后，向导自动衔接完整执行；也可用「启用已验证的聊天与任务」核对或恢复启用。自检会实际调用所选模型，并在合成目录验证隔离；只登录成功或列出模型不等于执行已通过。

自动原生观察覆盖当前用户所声明 Codex 资料目录中的本机原生会话，从启用时间起同步新通知与普通问题；观察范围与后来授权给独立工作模型的项目列表不同。原窗口控制仍逐次核对原会话来源、目录、owner 和回合。

配对期间只处理配对，不开放普通聊天和任务。请将配对码、AppSecret 和账号登录内容只用于自己的本机接入，不贴到 Issue 或共享截图中。

配置会绑定当前账号、模型、机器人和项目授权；账号、机器人、模型或授权发生变化时，需重新核对相应步骤。自动步骤按当前范围和类型持久记录，手动停止后不会反复自动拉起服务，也不会抢占主动自检的间隙。自动配置不会代替配对、扩大项目权限、自动信任钩子或批准浏览器应用访问。配置更新要求业务停止；已经运行的服务会继续使用原配置，不在处理中途改写配置。

## 在 QQ 中使用

首先发送 **主菜单**。菜单编号以当前收到的页面为准，文字指令继续可用。

| 操作 | 用法 |
| --- | --- |
| 查看功能入口 | `主菜单`、`菜单`，选择 Codex 聊天或 Codex 工作 |
| 查看已有会话 | 在工作菜单选择项目，进入「项目任务」或「选择已有任务」 |
| 指导、继续原会话 | 选择任务后直接输入要求；原会话正在执行时补充指导，空闲时继续同一对话 |
| 查看状态与结果 | 使用「任务详情」「查询任务状态」「查看任务结果」及原通知中的编号 |
| 取消原生回合 | 按通知中的项目名和 D 编号发送 `取消 项目名 D编号`；仅取消该引用对应且仍有效的回合 |
| 回答桌面原生问题 | `问题列表`、`查看问题 Q编号`、`回答 Q编号：答案`；多题按通知使用 `1=答案；2=答案` |
| 回答网关任务问题 | 按通知发送 `回答 B编号：答案`；B 与原生 Q 各自处理 |
| 新任务 | 完整执行就绪后，在已授权项目中选择「新建任务」，填写具体要求 |
| 图片与文件 | 直接发送附件，发完后回复 `文件已发完`；查看「接收状态」「文件状态」 |

A、D、T 编号带来源项目，复制通知展示的完整引用使用即可。不要把其他项目中同号的任务当作同一任务。未打开、已归档、异机或无法核对原 owner 的会话可能只提供状态，不接受远程控制；管理台和 QQ 会提示具体状态。

Q 回写须核对原请求、题目、选项、原回合及本人绑定；原卡片不匹配、敏感或超限时保留本机作答。QQ 显示“已登记”表示请求入队，“原客户端已接收”和最后执行结果会分别确认。结果未知时先在原客户端核对，勿反复发送相同操作。

QQ 聊天可按菜单管理人设和来源记忆，工作可查看队列、继续任务和交付结果。模型生成处于未验证状态时，菜单、已有记录与原生连接按各自状态使用，独立聊天和新任务生成保持关闭。

## 文件、审批与权限

图片和文件按接收状态落入本实例接收目录；只有明确的任务要求才用于模型分析。危险类型可能被隔离，保存成功不表示文件已完成恶意内容扫描。文件发送状态区分已取得平台回执、未发送和结果待核对；需要补发时先核对原状态。

网关自己的待审批操作可在本机管理台逐项核对；启用相应 QQ 审批功能时，以实际通知展示的完整请求及决定方式为准。批准只能作用于同一原请求和已授权范围，不能扩大文件或网络权限。

可选原生工具审批桥涉及 `PermissionRequest`、`PostToolUse`、`Interrupt` 钩子。用户仍须在 Codex 本机审阅并信任具体定义；设置文件存在不等于已经信任或运行验证通过。**浏览器和 Computer Use 的独立应用宿主授权仍在本机处理**，不能用普通 Q 答案、文件审批或 MCP 表单代替。

## 启动自动连接与关闭

安装启用的监听器在当前 Windows 用户登录后运行，订阅 Windows 窗口事件。Codex 桌面主窗口出现时，复用已在线的本实例机器人；离线且初始化、配对和授权条件满足时，通过原管理流程启动服务。安装或重新启用时 Codex 已打开，也会检查一次。

重复窗口事件按主进程和启动时间合并；当前用户、当前实例只有一个监听器。启动请求使用持久编号，结果不确定时不自动重放。同一次 Codex 运行中，用户手动停止的服务保持停止；下次重新启动客户端再连接。机器人网络重连沿用原服务机制。

在程序目录执行以下命令关闭监听器并移除本实例用户启动项：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Enable-CodexAutoConnect.ps1 -RuntimeDirectory "<本实例数据目录>" -Disable
```

去掉 `-Disable` 可重新启用。配置变更前会在本实例 `backups/desktop-autoconnect` 保存原配置和快捷方式。关闭监听器不会停止已经运行的机器人。

「停止机器人服务」停止接单、发送并保存状态；等进行中的任务完成或正常取消后再升级。**停止管理界面.cmd** 只停止管理台，关闭浏览器页也不会停止业务。完整移除程序时，先关闭监听器并正常停止业务和管理台，再删除对应程序目录；数据目录由你选择备份、保留或删除，不随程序卸载自动清除。

## 数据目录、备份和升级

在程序目录运行以下只读命令可查看实际路径：

```powershell
node packages/host-control/cli.mjs paths
```

若本实例使用自选数据目录，同样加上 `--data-dir "<本实例数据目录>"`。管理台「本机设置」也显示当前数据目录。默认数据根基于程序所在卷定位：一般在程序父目录的 `QQAgentData/users/<用户标识>/instances/default`；程序放在 `programs/<版本>` 时，基于 `programs` 的父目录。不同 Windows 用户各自生成标识和实例，程序路径中不固定用户名或盘符。

业务数据不能位于系统卷、程序目录、其他应用账号目录或盘符根。缓存与临时文件使用本项目自己的目录和环境配置，不修改全局环境或共享其他应用运行库。

| 数据 | 用途 |
| --- | --- |
| `management.sqlite`、`setup.sqlite` | 本机管理、绑定、授权和初始化操作记录 |
| `business/<机器人内部编号>/` | 任务、聊天、编号、问答、接收文件和业务状态 |
| `codex-account/`、`qq-connection/` | 本项目独立登录与加密 QQ 凭据 |
| `desktop-autoconnect*.json` | 自动连接配置、监听器状态和连接结果 |
| `diagnostics/`、`backups/` | 脱敏诊断和本应用备份 |

不要把数据目录、登录库、数据库、AppSecret、配对码或原始会话日志提交到 Git。诊断先在「本机设置 → 预览脱敏诊断」查看，再导出到本机 `diagnostics`；程序不会自动把该诊断上传。

升级前正常停止业务、管理台和监听器，分别备份程序与数据。把新程序解压到独立目录，用相同数据目录启动，再重新启用监听器。不要同时运行新旧副本。涉及程序、路径、CLI、模型或绑定的变化可能使独立执行证明失效，应按管理台提示主动重新自检；原生连接按自身兼容状态判断。

仅迁移本人本应用数据时，可使用以下独立入口；源服务必须先正常停止，目标必须是空的独立目录：

```powershell
node packages/host-control/cli.mjs import --source "<原本应用数据目录>" --data-dir "<新的空数据目录>" --confirm-own-data --retain-current-consent
```

该命令保留源目录、核对本应用身份和资料，不导入其他应用凭据，也不沿用旧路径执行证明。它用于同机、同 Windows 用户的本人实例迁移；跨机器或更换系统用户时，Windows 保护的凭据可能需重新登录或重新填写。不要为迁移而复制 Codex 桌面的凭据库。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 Node 或 CLI | 核对公共安装及 `PATH`，在新终端运行版本命令；不要借用其他应用私有运行时 |
| `ACCOUNT_CLI_VERSION_UNVERIFIED` | 使用已适配的账户版本；本次已核对 `0.167.0`、`0.167.0-alpha.3.2` 的隔离只读协议，未知补丁版本不自动放行 |
| 0.167 账户可连接但独立生成未就绪 | 0.167 的账户适配不提供独立模型执行许可；当前可用原生会话模式，完整执行须另行适配并通过当前环境验证 |
| `SYSTEM_DRIVE_STORAGE_FORBIDDEN` | 选择非系统盘独立程序/数据目录，勿修改目录 ACL 绕过 |
| 管理台地址打不开 | 再次运行打开入口，核对实际本机端口；状态不明而原进程仍存活时先核对，避免重复启动 |
| QQ 已连接但不能生成聊天/新任务 | 查看“独立模型执行”状态；在本机主动自检，通过后启用完整执行 |
| 等待桌面初始化或原窗口连接 | 用相同 Windows 用户打开 Codex 桌面并进入相关会话，刷新状态；核对当前版本兼容性 |
| 自动配置停在配对 | 回到发起配对的管理窗口查看当前有效码；发送到自己的机器人私聊，过期后按向导重新发起 |
| 管理台重启后原设置窗口失效 | 在当前窗口重新确认同一使用范围后继续；原配对码不会转交给其他窗口，结果未知的操作仍先核对 |
| 原生问题需本机回答 | 当前题目、原回合或请求无法完整核对，直接在原卡片作答；不要以普通文字绕过 |
| QQ 无法收到通知 | 核对服务、平台连接、发送窗口/限额和待核对记录；“入队”不等于平台已送达 |
| 启动后仍为手动停止 | 同一客户端运行期尊重手动停止；可在管理台明确启动，或下次正常启动客户端时再连接 |
| 提交结果未知 | 在本机核对原操作和会话结果；不通过重发或更换编号自动重放 |

原生接口依赖本机 Codex 协议，升级后可能需要适配。原生控制与 Q 已有实现和离线、真实只读连接验证；本次发布未完成真人 QQ 写入、重新登录 Windows、客户端冷启动或全新机器全流程验收。工具审批钩子信任和浏览器宿主授权各自保留本机步骤，不能据普通文件操作验收推断它们全部可用。

## 开发与发布

源码贡献前阅读根 [AGENTS.md](../AGENTS.md) 和 [团队职责](AGENT-TEAM.md)。项目目前不通过 npm 发布包，`private` 标记用于避免误发布；源码采用 [MIT](../LICENSE)。

```powershell
npm ci
npm run check
npm run check:config
npm test
```

源码和测试夹具应位于非系统盘。可通过 `QQ_TEST_ROOT` 指定该盘的独立测试目录，`QQ_TEST_EVIDENCE_ROOT` 与唯一的 `QQ_TEST_EVIDENCE_NAME` 保存本轮证据。离线测试包括合成数据和本机 HTTP，不自动登录、发送真实 QQ 消息或进行模型生成。

发布通过白名单导出新目录，不能直接压缩开发工作目录。以下占位符均需换成全新、外部的独立目录；不要把产物目录嵌入源码目录：

```powershell
node scripts/build-source.mjs prepare "<干净源码目录>"
node scripts/build-release.mjs prepare "<干净程序目录>"
# 在干净程序目录执行：
npm ci --omit=dev --ignore-scripts
# 回到源码目录执行：
node scripts/build-release.mjs seal "<干净程序目录>"
node scripts/build-archives.mjs "<干净源码目录>" "<干净程序目录>" "<全新输出目录>"
```

发布物包括源码 ZIP、带公共依赖的 Windows 程序 ZIP 和 `SHA256SUMS`。程序中的 `MANIFEST.json` 记录文件哈希。源码包不含 `node_modules`；两个包都不含本机数据、开发运行目录、账号、实例定位文件或私有历史文档。发布前检查清单、哈希和隐私审计；第三方许可详见 [声明](../THIRD_PARTY_NOTICES.md)。

[Windows CI 模板](ci/windows-ci.yml) 随源码提供。需要 GitHub Actions 时，由仓库维护者在具备工作流写入授权的环境中将它放入 `.github/workflows/ci.yml`；当前发布依靠上述本地验收流程，不自动扩大账号的 GitHub 权限。
